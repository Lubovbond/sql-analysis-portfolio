## 🚀 Проект: Конвейер предобработки сырых данных (Data Quality & ETL)

### 📈 Бизнес-контекст и задача
При выгрузке логов заказов из CRM-системы для последующего вывода в BI-дашборды (Yandex DataLens / Apache Superset) команда столкнулась с искажением ключевых метрик (средний чек, динамика выручки, Margin LTV). 

**Цель проекта:** Спроектировать воспроизводимый ETL-пайплайн для очистки сырых данных от технического «шума», аномалий и подготовки чистой аналитической витрины.

### 🛠 Стек технологий
* **SQL:** предварительная фильтрация, обработка NULL, логика подзапросов.
* **Python (Pandas, NumPy):** разведочный анализ данных (EDA), статистическая очистка от выбросов (метод перцентилей), обогащение данных.

---

### 1️⃣ Этап трансформации и фильтрации на уровне базы (SQL)
Для снижения нагрузки на память аналитического сервера, вся первичная валидация типов данных и отсечение заведомо некорректных логов (отмененные транзакции) происходят на этапе извлечения (Extract) с помощью обособленного **CTE**:

```sql
WITH validated_orders AS (
    SELECT 
        order_id,
        user_id,
        -- Замена пропущенных статусов на дефолтное значение
        COALESCE(status, 'canceled') AS order_status,
        -- Явное приведение типов для корректной работы со временем
        CAST(created_at AS TIMESTAMP) AS order_time,
        order_amount,
        cost
    FROM raw_crm_logs
    WHERE order_amount > 0 -- Отсекаем технические ошибки с нулевыми суммами
)
SELECT * 
FROM validated_orders
WHERE order_status = 'delivered'; -- В аналитическую витрину берем только доставленные заказы
```

### 2️⃣ Этап глубокой очистки от аномалий и обогащения (Python & Pandas)
Полученный плоский датасет содержит скрытые аномалии (например, массовые спам-заказы или сбои логирования, когда один пользователь генерирует сотни записей). Скрипт на Python производит финальный контроль качества (**Data Quality**):

```python
import pandas as pd
import numpy as np

# Загружаем подготовленный SQL-выборкой датасет
df = pd.read_csv('validated_orders.csv')

# 1. Удаление дубликатов строк, возникших при выгрузке логов
df = df.drop_duplicates()

# 2. Обработка пропусков в финансовых метриках
# Пропущенную себестоимость (cost) заполняем медианой по конкретной категории блюд/товаров
df['cost'] = df.groupby('category')['cost'].transform(lambda x: x.fillna(x.median()))

# 3. Статистическая очистка от аномальных выбросов (Главный паттерн!)
# Используем метод 95-го перцентиля, чтобы исключить экстремальные шумы
limit_95 = df['order_amount'].quantile(0.95)
df_clean = df[df['order_amount'] <= limit_95]

# 4. Обогащение данных для Margin LTV и визуализации в BI
# Рассчитываем чистую маржу с каждого заказа
df_clean['margin'] = df_clean['order_amount'] - df_clean['cost']
# Выделяем периоды для удобного построения графиков сезонности
df_clean['order_month'] = pd.to_datetime(df_clean['order_time']).dt.to_period('M')

# Экспортируем чистую витрину для BI-дашборда
df_clean.to_csv('clean_bi_orders.csv', index=False)
print("Витрина успешно сформирована. Объем выборки после фильтрации шума:", df_clean.shape[0])
```
